# Правила работы с проектом BIC

Эти инструкции действуют для всего репозитория на всех рабочих компьютерах проекта.
Контекст работы хранится в файлах проекта и передаётся вместе с исходниками.
Общение и документация проекта - на русском языке.

## Начало каждого нового чата

1. Прочитать этот файл, `PROJECT_STATE.md` и `DECISIONS.md` до изменения кода.
2. Проверить `git status --short` и относящиеся к задаче исходники. Сохранить существующие
   пользовательские изменения; не считать незакоммиченные файлы своими.
3. Использовать `README.md` и `INSTALL.md` для сборки и окружения. Проверить реальные
   пути и доступность инструментов на текущем компьютере.
4. Продолжить с зафиксированного состояния. Если заметки расходятся с кодом, установить
   актуальное поведение по коду и проверкам, затем исправить заметки. Не выдавать планы
   или результаты проверки на другом компьютере за подтверждённые здесь факты.

## Обязательная фиксация решений

- Каждое новое принятое решение по проекту записывать в `DECISIONS.md` в рамках той же
  задачи, до итогового ответа. Это касается архитектуры, поведения, интерфейсов, сборки,
  проверок, организации работы и явно заданных пользователем правил.
- Указывать уникальный последовательный ID, дату, статус, само решение, причину,
  последствия и затронутые файлы. Отличать принятое и реализованное от предложения.
- При пересмотре решения добавлять новую запись со ссылкой на предыдущую. Старую
  помечать как заменённую, не стирать историю. Повторное подтверждение без изменений
  не требует дубликата.
- В `PROJECT_STATE.md` поддерживать краткое актуальное состояние: реализованные функции,
  текущую задачу, результаты и границы проверок, оставшуюся работу, следующий шаг.
  Обновлять после изменения кода, проверки, принятия решения и перед передачей работы.
- Постоянные правила работы дополнительно отражать в `AGENTS.md`; инструкции по сборке
  и использованию - в `README.md`/`INSTALL.md`. Согласовывать связанные документы.
- Не сохранять пароли, токены, секреты и полный текст переписки. Фиксировать значимые
  решения и факты. Не объявлять задачу завершённой, пока контекст не обновлён.

## Работа на нескольких компьютерах

- Корень проекта: `C:\YD\Projects\BIC`. Открывать именно эту папку в Codex на каждой машине.
- Перед началом работы получить актуальные исходники вместе с `AGENTS.md`,
  `PROJECT_STATE.md`, `DECISIONS.md`; перед переходом на другую машину сохранить изменения
  и дождаться завершения используемой синхронизации.
- При передаче через Git включать файлы контекста в тот же коммит, что и изменения кода.
  Коммит и отправку выполнять только в рамках поручения пользователя, не автоматически
  из-за этих инструкций. Незакоммиченные файлы через Git не передаются.
- При конфликте синхронизации сопоставить обе версии решений и состояние кода, сохранить
  значимую историю и устранить повторяющиеся ID. Не заменять журнал целиком старой копией.
- Не переносить сборочные кэши как источник истины: каждый компьютер собирает проект
  локально. Наличие этих файлов не означает, что история чата или настройки Codex синхронизированы.

## Технические договорённости

- BIC: C++20, Win32, Unicode, MSVC 2022, Windows SDK, CMake и Ninja.
- Новые команды открытия Excel/Word/PowerPoint используют `OfficeDocument::Open`
  и `OpenOptions`; не копировать COM-логику в обработчики кнопок.
- Проверки выбирать по изменению. Для изменений C++ выполнять сборку и подходящие тесты;
  отдельно указывать, выполнялась ли реальная проверка Office и оконного поведения.
- Для изменений только документации проверить согласованность, ссылки и `git diff --check`;
  повторная сборка не обязательна.
- Предпочитать заданный `-BuildRoot` или `BIC_BUILD_ROOT`. Сейчас запасной путь в
  `build.ps1` - `D:\Dev\Build\BIC-Z7`, а в настройках VS Code - `C:\Dev\Build\BIC-Z7`.
  Не считать их согласованными и не менять молча. Путь последней проверки указан в состоянии.

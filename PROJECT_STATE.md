## Назначение и структура

Оконное приложение Business Information Center на C++20 / Win32 для Windows.
Пользователь работает поочерёдно на нескольких компьютерах Windows 10;
путь проекта на них одинаков: `C:\YD\Projects\BIC`.

- `src/main.cpp`: `wWinMain`, создание окна, цикл сообщений. При запуске окно занимает
  правую нижнюю четверть рабочей области основного монитора.
- `src/single_instance.*`: именованный mutex, активация уже запущенного экземпляра.
- `src/main_window.*`: кнопки «Реестр договоров», «Бланк ИП» и «Бланк КИ»,
  маршрутизация сообщений, показ/сворачивание окна.
- `src/tray_icon.*`, `src/window_hotkeys.*`: трей и Ctrl+Alt+M; восстановление значка
  после перезапуска Проводника, запасное сворачивание на панель задач.
- `src/contract_registry.*`: команда «Реестр договоров», задающая параметры общего открытия.
- `src/ip_letterhead.*`: команда «Бланк ИП», задающая параметры открытия Word.
- `src/ki_letterhead.*`: команда «Бланк КИ», задающая параметры открытия Word.
- `src/office_document.*`: общий интерфейс `OfficeDocument::Open(OpenOptions)` для
  Excel, Word и PowerPoint. Путь, тип приложения, размещение окна, режим чтения,
  использование доступного работающего приложения задаются параметрами.
  Для Excel при повторном вызове ищется открытая книга по полному пути.
- `tests/office_document_validation.cpp`: проверка ошибочных входных параметров без Office.

## Выполнено

1. Открытие Office вынесено из команды реестра в общий модуль. COM-ресурсы освобождаются
   автоматически; исходная `AutomationSecurity` восстанавливается после открытия.
2. Размещение окна: Keep, LeftHalf, RightHalf, Maximized, Rectangle; для половин экрана
   можно выбрать монитор. Excel использует HWND окна документа; Word задаёт
   положение и размер через Word.Window после активации документа.

   восстановления безопасности. Команда сама показывает сообщение об ошибке.

## Ограничения и дальнейшая работа

- `OfficeDocument::Open` синхронный: запуск Office или его диалог может задерживать UI BIC.
  Отдельный STA-поток с очередью пока только возможное улучшение, не реализован.
- Другие приложения Office требуют отдельной поддержки их объектной модели.
- Для PowerPoint требуется иной способ получения окна документа или отдельная
  ветка размещения; ветка HWND сейчас применяется к Excel и PowerPoint, а Word
  размещается через собственные свойства окна.
- Книги в Protected View и экземпляры Excel, недоступные через COM, могут не
  обнаружиться при поиске. Реальную проверку повторного открытия выполнить отдельно.
- Проверить реальные документы в трёх поддержанных приложениях, включая ошибку открытия,
  read_only и различные варианты размещения. Следующий технический шаг при продолжении -
  такая проверка либо новая задача пользователя.
- Пути сборки в `build.ps1` и VS Code различаются; использовать явно выбранный BuildRoot.
  Согласование путей пока не выполнено.
